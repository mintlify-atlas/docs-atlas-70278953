---
title: 'Fine-tuning ASR'
description: 'Fine-tune VibeVoice-ASR on your own audio data using LoRA (Low-Rank Adaptation) with single- or multi-GPU training.'
---

VibeVoice-ASR supports LoRA fine-tuning, which adapts the model to domain-specific speech using a small number of additional parameters. This is useful for improving accuracy on specialized vocabulary, accents, or recording conditions without retraining the full 7B-parameter model.

## Requirements

Install the base VibeVoice package first, then add `peft`:

```bash
pip install -e .
pip install peft
```

## Data format

Training data must be organized as pairs of audio files and JSON label files in the same directory:

```
toy_dataset/
├── 0.mp3
├── 0.json
├── 1.mp3
├── 1.json
└── ...
```

Each JSON file must follow this schema:

```json
{
  "audio_duration": 351.73,
  "audio_path": "0.mp3",
  "segments": [
    {
      "speaker": 0,
      "text": "Hey everyone, welcome back...",
      "start": 0.0,
      "end": 38.68
    },
    {
      "speaker": 1,
      "text": "Thanks for having me...",
      "start": 38.75,
      "end": 77.88
    }
  ],
  "customized_context": ["Tea Brew", "Aiden Host", "The property is near Meter Street."]
}
```

| Field | Type | Description |
|---|---|---|
| `audio_duration` | float | Total duration of the audio file in seconds |
| `audio_path` | string | Filename of the audio file (relative to the JSON file) |
| `segments` | array | List of transcription segments |
| `segments[].speaker` | integer | Zero-indexed speaker ID |
| `segments[].text` | string | Transcribed text for this segment |
| `segments[].start` | float | Segment start time in seconds |
| `segments[].end` | float | Segment end time in seconds |
| `customized_context` | array of strings | Optional domain-specific terms or context sentences |

<Note>
The `toy_dataset/` included in the repository contains **synthetic audio generated by VibeVoice TTS** for demonstration purposes only. When using your own data, prepare real audio recordings with accurate transcriptions and adjust hyperparameters based on your dataset size and domain.
</Note>

## Training workflow

<Steps>

<Step title="Prepare your dataset">

Organize audio and JSON label pairs in a single directory following the format above. Ensure audio paths in each JSON file are relative to the JSON file's location.

</Step>

<Step title="Run single-GPU training">

```bash
torchrun --nproc_per_node=1 finetuning-asr/lora_finetune.py \
  --model_path microsoft/VibeVoice-ASR \
  --data_dir ./toy_dataset \
  --output_dir ./output \
  --num_train_epochs 3 \
  --per_device_train_batch_size 1 \
  --learning_rate 1e-4 \
  --bf16 \
  --report_to none
```

</Step>

<Step title="(Optional) Run multi-GPU training">

To use multiple GPUs, set `CUDA_VISIBLE_DEVICES` and increase `--nproc_per_node`:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 torchrun --nproc_per_node=4 finetuning-asr/lora_finetune.py \
  --model_path microsoft/VibeVoice-ASR \
  --data_dir ./toy_dataset \
  --output_dir ./output \
  --num_train_epochs 3 \
  --per_device_train_batch_size 1 \
  --learning_rate 1e-4 \
  --bf16 \
  --report_to none
```

</Step>

<Step title="Run inference with the fine-tuned model">

```bash
python finetuning-asr/inference_lora.py \
  --base_model microsoft/VibeVoice-ASR \
  --lora_path ./output \
  --audio_file ./toy_dataset/0.mp3 \
  --context_info "Tea Brew, Aiden Host"
```

</Step>

</Steps>

## Key training parameters

| Parameter | Default | Description |
|---|---|---|
| `--lora_r` | 16 | LoRA rank. Lower = fewer parameters, higher = more expressive |
| `--lora_alpha` | 32 | LoRA scaling factor. Typically set to 2× the rank |
| `--lora_dropout` | 0.05 | Dropout applied to LoRA layers |
| `--per_device_train_batch_size` | 8 | Batch size per device |
| `--gradient_accumulation_steps` | 1 | Effective batch size = `batch_size × grad_accum` |
| `--learning_rate` | 5e-5 | Learning rate. A value of 1e-4 to 2e-4 is typical for LoRA |
| `--gradient_checkpointing` | False | Enable to reduce GPU memory usage at the cost of compute |
| `--use_customized_context` | True | Pass `customized_context` from JSON as additional model context |
| `--max_audio_length` | None | Skip audio files longer than this value (in seconds) |
| `--warmup_ratio` | — | Fraction of training steps used for learning rate warm-up |
| `--weight_decay` | — | L2 regularization coefficient |
| `--max_grad_norm` | — | Gradient clipping threshold |

All standard Hugging Face `TrainingArguments` flags are accepted. See the [Transformers documentation](https://huggingface.co/docs/transformers/main_classes/trainer#transformers.TrainingArguments) for the full list.

## Merging LoRA weights (optional)

Merging the LoRA adapter into the base model weights eliminates the adapter overhead at inference time and produces a single self-contained checkpoint:

```python
from peft import PeftModel
from vibevoice.models.asr import VibeVoiceASRForConditionalGeneration

# Load base model and LoRA adapter
model = VibeVoiceASRForConditionalGeneration.from_pretrained(
    "microsoft/VibeVoice-ASR"
)
model = PeftModel.from_pretrained(model, "./output")

# Merge weights and save
model = model.merge_and_unload()
model.save_pretrained("./merged_model")
```

The merged checkpoint at `./merged_model` can be used with `inference_lora.py` or loaded directly with `from_pretrained` as a standard model.
